# mamori 守り

**実データのまま生成AIを使う。実データは送らずに。**

English: [README.md](README.md) ／ 中文: [README.zh.md](README.zh.md)

顧客からのメールが目の前にあり、返信の下書きを数秒で書けるモデルもある。
だから氏名を伏せて打ち直し、伏せ字の付け方が途中でぶれ、署名欄の電話番号を
見落とし、結局は自分で書いたほうがましな下書きができあがる。

`mamori` はその作業を、ローカルで、一貫したやり方で肩代わりする。

```text
あなたが書く                    モデルが見る                   あなたが受け取る
─────────────────────────────  ─────────────────────────────  ─────────────────────────────
田中太郎さんへ                  <PERSON_001>さんへ              田中太郎さんへ
tanaka@example.com から        <EMAIL_001> から                tanaka@example.com から
メールが届きました。            メールが届きました。             メールが届きました。
```

`<PERSON_001>` から `田中太郎` に戻す対応表が手元の端末を出ることはない。

## 動かして見る

インストール以外に何も要らない。

```bash
pip install mamori
mamori demo
```

短いシナリオが5つ。それぞれ実際に聞かれる問いに答える。
モデルには何が見えて自分の言葉は戻ってくるのか。
プレースホルダーがストリームで分割されて届いたらどうなるのか。
1文ではなく文書でも通用するのか。間違えたときどうするのか。
テキストにパスワードが入っていたらどうなるのか。

次に自分のもので試す。

```bash
mamori demo --file draft.txt
mamori demo --scenario roundtrip --text "田中太郎さんに090-1234-5678で連絡して"
```

```text
you wrote
  Dear Jane Doe, reach me at jane.doe@example.com

the model sees
  Dear <PERSON_001>, reach me at <EMAIL_001>

replaced 2 value(s), and what found each one:
  <PERSON_001>        PERSON        en          0.90
  <EMAIL_001>         EMAIL         universal   1.00
```

右の2列は「どの規則集が反応したか」と「どれくらい確信していたか」である。
**「なぜこれが置換されたのか」に答えが出る。**

### 実際のモデルに対して

`--live` は保護してから指定したモデルに実際に送り、答えを復元する。
シミュレーションではなく往復の全部である。

```bash
mamori demo --live --model llama3.1:8b --api http://localhost:11434/v1/ \
  --text "田中太郎さんへ。tanaka@example.com までご返信ください。3行で要約して。"
```

```text
what actually goes over the wire
  <PERSON_001>さんへ。<EMAIL_001> までご返信ください。3行で要約して。

what the model said (placeholders intact)
  <PERSON_001>さまへ
  <COMPANY_NAME_001>からご連絡いたします。

restored into your own words
  田中太郎さまへ
  株式会社さくら商事からご連絡いたします。
```

OpenAI互換エンドポイントなら何でもよい（Ollama、vLLM、LM Studio、
`--api-key-env` を使えばホスティングされたAPIも）。

## 使い方

```python
import mamori

with mamori.PrivacySession() as session:
    protected = session.protect("田中太郎さんに tanaka@example.com で連絡して")
    # -> '<PERSON_001>さんに <EMAIL_001> で連絡して'

    answer = call_your_favourite_llm(protected.protected_text)

    print(session.restore(answer).text)
```

1つのセッションが1つの会話にあたる。同じ値はセッションが続くかぎり同じ
プレースホルダを保つので、モデルは2箇所の言及が同一人物だと判断でき、
5ターン目の応答も1ターン目の値で復元できる。

### ストリーミング

応答はトークン単位で届くので、`<PERSON_001>` は `<PER` / `SON_0` / `01>` に
分かれてやってくる。届いたそばから復元できる。

```python
stream = session.stream_restore()
for chunk in llm_response_stream:
    print(stream.feed(chunk), end="", flush=True)
print(stream.finish())
```

どのような分割で流れてきても、**応答全体を `restore()` にかけた結果と
1文字も違わない**。Hypothesis であらゆる分割位置を検証している。
「たいてい一致する」ストリーミング実装は、モデルが選んだトークン境界次第で
壊れる。再現しないうえ、実データが崩れて初めて気付く。

### コマンドラインから

```bash
mamori inspect -f draft.txt
```

```text
4 detected:
      0:4     PERSON           <PERSON_001>       田***                (ja, 0.90)
     12:30    EMAIL            <EMAIL_001>        t*****************   (universal, 1.00)
     45:58    PHONE            <PHONE_001>        0************        (ja, 0.90)
     70:94    INTERNAL_URL     <INTERNAL_URL_001> h***********************  (universal, 0.90)
```

最後の列は命中した規則セットで、どの言語のパックが見つけたかがわかる。
`mamori demo` は往復全体を実行する。プレースホルダが改変されて返ってきた
応答も含むので、復旧の挙動をそのまま確認できる。

## アプリを書き換えずに使う

動いているアプリをライブラリのために書き直す人はいない。
OpenAI互換APIを叩いているアプリなら、mamori を前に置いて文字列を1つ変えるだけでよい。

```bash
mamori serve --upstream https://api.openai.com/v1/
```

```text
mamori proxy on http://127.0.0.1:8100/v1/
  upstream        https://api.openai.com/v1/
  detection       all locales, recall_first
  briefing        prepended
```

アプリの向き先を `http://127.0.0.1:8100/v1/` にする。他は何も変えない。
送信時に全メッセージを保護し、応答を復元して返す。
何を置換したかはログに出るが、**値そのものは決してログに出ない**。

```text
  1 message(s), replaced EMAILx1, PERSONx1, PHONEx1
```

ストリーミングにも対応する。`<PER` `SON_0` `01>` と分割されて届く
プレースホルダーも保持して復元する。認証情報が含まれていればリクエストは
転送されずに停止する。既定では**このPCからしか繋がらない**。
そのポートに到達できる者は誰でも文書を通せてしまうからである。
→ [ADR 0018](docs/adr/0018-a-proxy-on-the-standard-library.md)

### 2ターン目

既定ではリクエスト間に何も保持しない。スコープは1回で使い切り、応答とともに
破棄される。ほとんどのクライアントではこれで問題ない。毎ターン会話全体を送り
直すので、同じ値が同じ順で同じプレースホルダに落ちる——この主張は0.16から
**文章ではなくテストになった**。

壊れるのは、履歴をサービス側が持っていて新しいターンだけを送るクライアントだ。
サービスは `<PERSON_001>` について答え、こちらのプロセスは `<PERSON_001>` を
知らない。人間にトークンが表示される。

```bash
mamori serve --conversations --upstream https://api.openai.com/v1/
```

応答に `X-Mamori-Session` が付く。それを返すクライアントはターンをまたいで
プレースホルダを保ち、返さないクライアントは従来どおり毎回新しいスコープを
得る。**トークンはサーバーが発行し、呼び出し側からは受け取らない**——その先に
あるのは実データの表であり、外部から推測できる識別子は他人の表を読む手段に
なる。未知のトークンは「未知だ」と答えず、静かに新しい会話を始める。

会話は30分無操作で失効し、同時に保持するのは最大64件。どちらの上限も破棄を
伴い、ディスクには何も書かない。動かして見るには:

```bash
mamori demo --scenario conversation
```

[ADR 0028](docs/adr/0028-the-server-names-the-conversation.md) を参照。

## 誰も打っていないプロンプト

プロンプトは書かれるものから**組み立てられる**ものになりつつある。検索層が
ノートから該当箇所を選び、それぞれの出所をヘッダに付け、まとめて描画する。
1つの文書に3種類のものが同居しており、これらは同じ種類ではない。

```text
[fbd4c2a631fd] /home/p.doe/notes/meeting-log.md (Meeting)[464:562]
Met with Priya Raman from Northwind Ltd on Tuesday.
```

```text
[fbd4c2a631fd] /home/<PERSON_001>/notes/meeting-log.md (Meeting)[464:562]
Met with <PERSON_002> from <COMPANY_NAME_001> on Tuesday.
```

**ヘッダは人を名指ししている。** ホームディレクトリは署名欄と同じくらい確実に
所有者を特定するし、その名前は本文のどこにも出てこないことが多い。置換するのは
その1区画だけである。パスの残りは来歴であり、下流の何かがそれを検証している
可能性がある。`runner`、`Public`、`www-data` などのシステムアカウントは
閉じたリストで除外する。

**構造には触れない。** `[fbd4c2a631fd]`、`[464:562]`、`//fileserver/team/`。
語を過剰に伏せれば回答品質を損なうだけだが、**ハッシュを伏せればそのパッケージの
IDは検証できなくなる**——下流から見れば、改竄されたものと区別がつかない。同梱
データセットではこれらを「普通の文字列」としてラベル付けしてあるので、そこで
置換が起きればテストが落ちる。

**引用はそのまま戻る。** モデルの引用を送信内容と突き合わせて検証する仕組みが
あるなら、復元は1文字単位で一致しなければならない。1文字ずれれば、それは
「伏せられた引用」ではなく「捏造された引用」として読まれる。生成した回答300件、
300件とも完全一致。

```python
result = session.protect(package)
result.reversible      # マスクされたものがあれば False
result.masked_types    # ('PHONE',) — 型だけ。値は決して出さない
```

テスト上、`<PERSON_001>` と `[REDACTED]` は同じくらい「置換済み」に見えるが、
元に戻せるのは片方だけである。主張を検証する側にとって、これは
*unsupported*（裏付けなし）と *unverifiable*（検証不能）の違いになる。

```bash
mamori demo --scenario package
```

この形は [tsumugi](https://github.com/Nananananana/tsumugi) を相手に測定した。
tsumugi はまさにこの形を描画し、後段で引用を検証する。両プロジェクトは互いに
依存していない。→ [ADR 0029](docs/adr/0029-a-prompt-nobody-typed.md)

## チャットではなくエージェント

アプリケーションがエージェントになった時点で、個人情報の大半は散文から出ていく。
ツール呼び出しの引数の中にある。

```json
{"to": "jane.doe@example.com", "employee_id": "E-45033",
 "body": "Dear Jane Doe, call 415-555-0198."}
```

1回の呼び出しに4つの値。`mamori serve` はそのすべてを保護し、モデルがツールを
呼び返したときに元に戻す。

```json
{"to": "<EMAIL_001>", "employee_id": "<EMPLOYEE_ID_001>",
 "body": "Dear <PERSON_002>, call <PHONE_001>."}
```

**ペイロードではキーがラベルである。** `"employee_id"` は、文中の `社員番号:`
と同じくらい明確に値の正体を語っている。しかも周囲に散文がないので、規則に
二度目のチャンスはない。7種類のキー群を、英語・日本語・中国語の表記で読む。
ただし裸の `"name"` は**あえて含めていない**。JSONにおける `name` は人名より
ツール名であることのほうが遥かに多く、エージェントが呼ぼうとしている関数の名前を
伏せれば、壊れるのは呼び出しである。

**構造は負例である。** `send_email`、`call_0042`、JSONスキーマ、enum——いずれも
触れず、テストで固定してある。もし保護の結果パースできない引数ができてしまったら、
そのリクエストは転送されずに**拒否**される。漏れは目に見えるが、3時間後に別プロセスで
壊れるペイロードは目に見えない。

**そして戻ってくる。** 文ではなくツール呼び出しで答えるモデルに対しても、引数は
復元される——ストリーミング中も同様で、各呼び出しはそれぞれ独立したテキストの流れ
として扱われる。これがないと、アプリケーションは `<EMAIL_001>` 宛にメールを送る。
それは「漏洩」ではなく「バグ」に見える失敗である。

```bash
mamori demo --scenario agent
```

`v0.18` ではもう1つ修正した。**仮名が1文字あるだけで、文書全体に対して中国語の規則が
停止していた**。そのため「件名が日本語、本文が中国語」のペイロードは本文が素のまま
送られていた。文字体系についての根拠は、いまはその文の終わりまでしか届かない。
→ [ADR 0030](docs/adr/0030-a-tool-call-is-text.md)

## 運用に入れる前に

本番に近づける前にチームが必要とするものが3つある。どれも検出規則ではない。

### コミットされる前に

**リポジトリ経由**でモデルに届く値は、このライブラリを一度も通らない。実在の住所が
入ったプロンプトテンプレート、サポートチケットから作ったフィクスチャ、出力セルに
問い合わせ内容が残ったままのノートブック。

```bash
mamori lint
```

```text
prompts/renewal.md:14: PERSON (0.90, en) J*******
prompts/renewal.md:14: EMAIL (1.00, universal) j**********@e******.com
fixtures/ticket.json:3: PHONE (0.90, en) 4***********

3 finding(s) in 2 file(s); 0 credential(s).
```

**値は決して出力しない。** この出力はCIログに残る。CIログは保存され、検索でき、
そしてしばしばリポジトリ本体より広く読まれる。

**資格情報では失敗し、それ以外は報告にとどめる。** 鍵の流出はインシデントである。
フィクスチャに顧客名が入っているかどうかは、誰かが意図して決めるべきことだ。
両方で異常終了するリンタは、`--no-verify` を覚えさせるだけである。反対の判断を
したリポジトリのために `--fail-on any` がある。

このリポジトリ自身のドキュメントに向けたところ、初回でバグを見つけた。GitHubの
URLは、base64鍵とまったく同じ文字種の長い並びなのである。

### 止まってほしいとき

既定では、迷いは「送る」側に倒れる。`min_confidence` を下回った検出は捨てられ、
値を含んだままテキストが出ていく。法務、医療、そして**漏洩のコストが回答品質で
測れない**すべての現場のために:

```python
MamoriConfig(min_confidence=0.85, uncertain="refuse")
```

```text
PolicyViolationError: 1 detection(s) below the confidence threshold and this
policy refuses rather than discards them (closest 0.50); nothing sent
```

型と確信度だけ。値は出さない。既定の `min_confidence=0.0` では何も起きない——
0を下回るものはないからである。2つの設定は1つのダイヤルであり、こちらは
「確信が尽きた場所で何が起きるか」を決める側にあたる。

### タグに見えないプレースホルダ

HTML文書の中の `<PERSON_001>` は未知の要素である。ブラウザはそれを落とすし、
文書を編集せよと言われたモデルは、トークンではなくタグを見せられていることになる。

```python
MamoriConfig(placeholder_style="square")   # [PERSON_001]
```

この設定が何であっても復元はすべての形式を受け付ける。ある形式で保護した文書を、
別の設定のセッションで復元してもよい。プレースホルダの同一性は `(型, 連番)` の組で
あって、括弧は見た目にすぎない。

## 対応言語

日本語・英語・中国語。1つの文書に混在していても扱える。

```text
田中太郎さんへ                        ->  <PERSON_001>さんへ
CC: Mr. John Smith (Acme Inc.)       ->  CC: Mr. <PERSON_003> (<COMPANY_NAME_002>)
张伟先生，请拨打 13812345678          ->  <PERSON_004>先生，请拨打 <PHONE_003>
```

規則は言語パックに分かれており、テキストが根拠を示したパックだけが動く。
既定では全パックが有効になる。**文書に想定外の言語が混じっている状況こそ、
誰も手作業で伏せていない状況**だからである。範囲がわかっている場合は
`locales=` で絞る。

```python
mamori.PrivacySession(locales=["ja", "en"])
```

```bash
mamori locales
```

```text
  en  English     16 rules  runs on: latin
  ja  Japanese    11 rules  runs on: han, kana
  zh  Chinese     11 rules  runs on: han  (not when: kana)
```

肝は最後の行にある。中国語と日本語は漢字を共有するため、両者の姓リストは
互いのテキスト上で発火し続け、普通の語を人名に変えてしまう。
判定材料になるのは仮名である。仮名は日本語には現れ、中国語には決して現れない。
したがってテキストに仮名があれば中国語規則は停止する。漢字のみの場合は
判定できないので両方を走らせ、過剰検出する側に倒す。
プレースホルダが1つ増える損失は回答品質だが、名前を1つ見逃す損失は
このライブラリが存在する理由そのものだからである。

メールアドレス・資格情報・カード番号・内部アドレスは言語非依存で常に動く。
言語の追加はモジュール1つと登録1行で済む（`register_locale` を参照）。

## 切り替えられる

検出は固定の手順ではなく、**パスの並び**である。各パスはテキストと
「それまでのパスが見つけたもの」の両方を見る。

```text
rules            汎用パターン + 該当する言語パック
  ↓
co-occurrence    しきい値以上の確信度で確定した値を、
                 同じテキスト内の他の出現箇所でも拾う
```

2つ目のパスが必要な理由はこれである。**ある文で敬称によって氏名が確定したら、
同じ文書の他の言及も同じ人物である。**しかし個々の言及だけを見る規則には
それが分からない。

```text
尊敬的张伟先生：              ← 敬称で確定する
本次评审由张伟主持。           ← ここには何の手がかりも無い
请张伟在周五前回复。           ← ここにも無い
```

3箇所とも保護される。中国語ではこれは最適化ではなく、
**他に手がかりが存在しない**ため必須である。

切り替え可能な設定はすべて1つのオブジェクトに集約した。

```python
mamori.PrivacySession(
    config=mamori.MamoriConfig(
        locales=["ja", "en"],
        min_confidence=0.7,  # 確信度の低い検出を無視：誤検出は減り、網羅性も下がる
        co_occurrence=True,
    )
)
```

`MamoriConfig` はファイル形式について何の意見も持たない。
`from_mapping()` は**解析済みのマッピング**を受け取るので、
JSON / TOML / YAML / dict リテラルのどれを使うかは呼び出し側が決める。
ライブラリ本体のランタイム依存は引き続きゼロである。

```bash
mamori config                       # 実際に使われる設定と、どの層から来たか
mamori protect --min-confidence 0.7 -f draft.txt
```

設定は後勝ちで重なる：既定値 → `--config` → `MAMORI_*` 環境変数 → コマンドライン引数。
**未知のキーは無視せず拒否する。** プライバシー設定のタイプミスが黙って
無視されるのは最悪の結果である（締めたつもりで締まっていない）。

### 匿名化漏れを優先する

各規則は**ティア**を宣言する。**core** は「それ以外である可能性が低いもの」に
固定された規則——チェックディジット、ベンダー接頭辞、敬称、ラベル。
**wide** は形だけで判断する規則——数字10桁、大文字始まりの2語、
長いランダム風トークン。どちらを走らせるかは stance が決め、
**既定は recall_first**（wide も走らせる）である。

| | leak rate | | over-redaction | |
|---|---|---|---|---|
| | balanced | **recall_first** | balanced | **recall_first** |
| `ja-core` | 0.68% | **0.00%** | 0.62% | **2.78%** |
| `en-core` | 1.93% | **0.64%** | 0.00% | **0.72%** |
| `zh-core` | 0.00% | **0.00%** | 1.63% | **2.94%** |
| `ja-docs` | 0.33% | **0.33%** | 0.18% | **1.06%** |
| `en-docs` | 20.02% | **3.50%** | 0.03% | **0.90%** |
| `zh-docs` | 2.37% | **2.37%** | 0.40% | **1.20%** |
| `ja-context` | 0.00% | **0.00%** | 0.00% | **0.00%** |
| `en-context` | 46.85% | **6.31%** | 0.00% | **0.92%** |
| `zh-context` | 0.00% | **0.00%** | 0.00% | **0.53%** |
| `ja-agent` | 0.00% | **0.00%** | 0.00% | **0.00%** |
| `en-agent` | 0.00% | **0.00%** | 0.00% | **0.00%** |
| `zh-agent` | 0.00% | **0.00%** | 0.00% | **0.00%** |

読むべきは `-docs` の行である。実際に送られる長さの業務文書であり、
`-core` は中央値44文字の文断片にすぎない。`v0.9` より前にこのプロジェクトが
公開してきた数字は、すべて後者だけから出ていた。

**`en-docs` の balanced は漏洩率 20.29%** ——
機微な文字の5分の1である。文書には手がかりの無い人名が大量にある
（出席者一覧、署名の下、「報告者:」の後ろ）。
これが recall_first を既定にしている最大の根拠であり、
自分のテキストで測る前に既定を切ってはいけない理由でもある。
→ [ADR 0025](docs/adr/0025-measure-at-the-length-people-send.md)

これがトレードオフである。埋もれさせずに書いておく。
**見逃しは静かで取り返しがつかない。誤検出は「置換すべきでない語が置換された」
という目に見える形で現れる。** 保護後テキストを読んだ人は後者に気付くが、
置換されなかった氏名には誰も気付かない。

```bash
mamori protect --stance balanced -f draft.txt   # 誤検出を減らしたいとき
mamori eval --stance balanced                   # どちらも測れる
```

**stance はセキュリティ上の判断を一切変えない。** 何を送ってよいかはポリシーが
決め、1文字につき1検出という解決も変わらず、資格情報は依然として遮断される。
stance が変えるのは「候補を何件出すか」だけである。だからこそ
「recall_first は balanced より漏らすことがない」を**テストとして固定**できる。

wide 規則は LOW confidence なので、stance を変えずに `min_confidence` で
落とすこともできる。同じトレードオフに対する粒度違いの2つのつまみである。

## 検出が間違えたとき

間違える。挨拶文の手がかりは間違うより当たるほうがはるかに多いが、
`Dear Monday,` は外れる側である。そう言えばよい。

```bash
mamori correct Monday --never --note "a weekday, not a name"
mamori correct Acme   --always COMPANY_NAME --note "trading name, no suffix"
```

後者は `v0.1` から記録されている既知の穴を塞ぐ ―
法人格接尾辞の無い商号（`Acme`、`田中商事`）。
一般には正規表現で届かないが、**自分のデータについてなら運用者が決着させられる。**

ログは追記のみで、ある値について最後に下した判断が有効になる。
取り消しは反対の判断を追記することであり、何も削除されない。
規則もプロンプトも書き換えない。ログを外せば完全に元の挙動に戻る。

```bash
mamori corrections     # 何を判断したか、その代償は何か
```

**`--never` は mamori で唯一「保護を減らす」操作である。**だから狭く保つ。
除外した値は `mamori privacy` が全て名指しし、警告として終了コードを 0 以外にする
（デプロイ時のチェックで落とせる）。そして**認証情報は決して除外できない。**

```text
error: that value looks like a credential (API_KEY), and a credential cannot
be ruled 'never'. Nothing was written -- recording it would have put the
credential in a file on disk. Rotate it instead.
```

この拒否は**追記する前に**、独立した3箇所で行われる。
→ [ADR 0024](docs/adr/0024-corrections-are-appended-applied-at-read.md)

## トークンではなく読める値を入れる

`<PERSON_001>` だらけのテキストではうまく推論できないモデルがある。
読める値に置き換えたほうが良い答えが返ることが多い。

```json
{"surrogates": ["PERSON", "EMAIL", "PHONE"]}
```

```text
入力    田中太郎さんへ。tanaka@example.com か 090-1234-5678 まで。
送信    山田一郎さんへ。a.person@example.com か 090-0000-0100 まで。
復元    田中太郎さんへ。tanaka@example.com か 090-1234-5678 まで。
```

メールアドレスと電話番号は文書用に予約された範囲（RFC 2606、未割当の0000番）
から取っている。**外に出ても、どこにも届かず何の意味も持たない。**
一方**人名には予約された集合が存在しない。** そこが残るリスクである。

**既定では無効**であり、有効にする前にその理由を理解しておく価値がある。
復元されなかった `<PERSON_001>` は一目で分かる。
復元されなかった `山田一郎` は**別人についての自然な文**であり、誰も気づかない。
プレースホルダーは形で認識できるので、モデルが多少崩しても復元できる。
代替値はただの名前なので、一致するかしないかのどちらかである。

mamori にできるのは**知らせること**である。
`RestorationResult.missing` に戻らなかったものが並ぶ（毎回確認すること）。
`mamori privacy` は代替値が有効なとき必ず警告し、
どのプールが予約済みでどれが単なる創作かを明示する。

```bash
mamori demo --scenario surrogates
```

→ [ADR 0026](docs/adr/0026-surrogates-trade-obviousness-for-readability.md)

## 自分のデータが実際どう扱われているのか

聞けばよい。

```bash
mamori privacy
```

答えは README ではなく**あなたの設定から**計算される。
どの型がブロックされ、どの型が置換されるか。検出用モデルがどこにあり、
信頼境界がそれを許可するか。何がどこに保持されるか。
露出を広げる設定は警告として出力され、終了コードが 0 でなくなる
（デプロイ時のチェックで落とせる）。

その下に、設定に関係なく成り立つ主張が並ぶ。
**それぞれに「壊れたら落ちるテスト」の名前が付いている。**

```text
  - Pattern detection contacts nothing. No socket is opened to protect a
    document with the default detectors.
    checked by test_promises.py::TestNothingLeavesTheMachine
```

このテストは実在する。`tests/test_promises.py` は `socket.connect` を
例外を投げる関数に差し替えた上で、既定の全経路（全言語パック、評価基盤、
コマンドライン）を走らせる。将来どこかの依存が外に通信を始めたら、
利用者の環境ではなく**ビルドで落ちる**。README の主張は説明ではなく仕様である。
→ [ADR 0019](docs/adr/0019-privacy-is-a-report-not-a-promise.md)、
[ADR 0020](docs/adr/0020-the-promises-are-checked-by-machine.md)

最後の節は mamori が**確認できないこと**を並べる。
たとえば送信先サービスがプロンプトを保持するかどうかは、ここからは知り得ない。
知っているふりをする報告は、黙っている報告より悪い。

## モデルを繋ぐ ― 同じPCでも、社内サーバーでも

現実的な構成はノートPCではない。チームで共有する1台のGPUマシンである。

```json
{"llm": {"model": "qwen2.5:72b", "base_url": "http://llm01.corp:8000/v1/"}}
```

```bash
mamori llm --check     # どこにあるか、許可されるか、応答するか
```

```text
  model           qwen2.5:72b
  endpoint        http://llm01.corp:8000/v1/
  host            private (another machine)
  trust boundary  private_network
  reachable       yes
```

`base_url` を書かなければ同じPC上のモデルを使う。他に変えるものは何もない。

拒否されるのは**公開エンドポイント**である。検出器は保護*前*のテキストを
受け取るので、社内ネットワークの外にあるエンドポイントは検出器ではなく
漏洩経路そのものである。しかもそれを最初の1件を処理する時ではなく、
起動時に告げる。

```text
REFUSED. This model will not be used:
  'api.openai.com' looks external, which is outside the private_network trust
  boundary.
```

境界は3つ。`same_host` / `private_network`（既定）/ `anywhere`。
`trusted_hosts` に明記されたホストはどの境界でも許可される ―
運用者がホストを名指しするのは「判断した」ということだからである。
→ [ADR 0015](docs/adr/0015-a-trust-boundary-not-a-localhost-check.md)

### モデルもライブラリも差し替えられる

モデルの切り替えは設定項目1つ。*繋ぎ方*の切り替えも1行で、
このライブラリに依存関係は増えない。

```python
from mamori.infrastructure.llm import CallableProvider, register_llm_provider

# 既に同一プロセス内に読み込まれているモデル。ライブラリは何でもよく、HTTPも不要。
provider = CallableProvider(my_pipeline, name="local-transformers")

# 設定ファイルから名前で選べるようにする。
register_llm_provider("vllm", lambda endpoint: MyVLLMProvider(endpoint))
```

```python
from mamori import MamoriConfig

session = MamoriConfig.from_mapping(settings).session()
```

同梱の Provider は `urllib` だけで OpenAI 互換 HTTP を話す。
実行時依存ゼロはゼロのままである。
→ [ADR 0016](docs/adr/0016-the-model-and-the-client-are-both-replaceable.md)

モデルが何をしようと、次の3つが成り立つ。

- **増やすことしかできない。** 「何も報告するな」と言い含められても、
  結果は規則だけの状態に戻るだけ。それは前バージョンまでの出荷状態である。
- **出力はテキストと照合される。** オフセットが範囲内にあり、報告された値が
  その区間の文字と完全一致しなければ破棄する。幻覚したスパンが文書から
  切り取られることはない。
- **モデルの失敗はリクエストの失敗ではない。** モデルが無い・遅い・壊れている
  のは「検出器が弱い」状態であって、処理停止ではない。
  `require_model` で逆にできる。

APIキーは設定ファイルには書かない。環境変数名を指定する
（`{"api_key_env": "LLM_API_KEY"}`）。リテラルの `api_key` は拒否する。

## プロンプト

関わるモデルは2つあり、向きが逆である。どちらのプロンプトも読めて変更できる。

**サービスLLM**にはプレースホルダをそのまま返すよう伝える。
ローカルモデルは不要で、即座に元が取れる。

```python
system = session.external_system_prompt() + "

" + your_own_system_prompt
```

無傷で返ってきたプレースホルダは、復元処理が改変から復旧しなくて済んだ分である。

**ローカルLLM**にはパターンでは届かない対象を探させる。
前置きの無い英語氏名、中国語の人名、普通名詞に見えるコードネーム。
そのプロンプトには**正規表現の作業で得た知見をすべて載せてある**。

```bash
mamori prompt detection
```

```text
## What looks sensitive and is not

- Many ordinary words begin with a character that is also a surname. 森林 is a
  forest, not 森 and 林. 原因, 金額, 石油, 田舎 and 林檎 are words.
- Two capitalised words are usually not a name. Headings, products, departments,
  weekdays and sentence openers all look identical.
```

これらは**正規表現についての知識ではなく、言語についての知識**だからである。

### 社内ルールを足す・既存ルールを削る

guidance は1件ずつ ID を持つ。ライブラリが知りようのないことを足し、
合わないものを外せる。**フォーク不要**。

```json
{"prompts": {"detection": {
  "disable": ["en.person.unanchored"],
  "add": [{"id": "acme.case", "text": "案件番号は ACME-12345 の形式である。"}]

```

```bash
mamori prompt detection --guidance   # ID一覧。ここから disable できる
```

**存在しない ID の disable は拒否する。** しかも設定を読み込んだ時点で拒否する
（何ヶ月も後ではなく）。外したつもりで外れていない状態を作らないためである。

## 難しいのは3か所

`mamori` の実装量の大半は、素朴に作ると必ず間違える部分に費やされている。

**モデルはプレースホルダをそのまま返さない。** `<PERSON_001>` は `PERSON_001`、
`<PERSON_1>`、`<person_001>`、`＜PERSON_001＞` になって戻ってくる。
復元処理は**表記には寛容、同一性には厳格**に作ってある。正規化した
`(型, 番号)` の組がそのセッションで実際に払い出されたものと一致したときだけ
置換する。それ以外は報告するだけで解決しない。応答は信用できない入力であり、
応答側が選んだ文字列で対応表を引かせることは、対応表を1回1件ずつ読み出させる
ことに等しい。

**日本語には語境界が無く、正規化するとオフセットがずれる。**
`ｔａｎａｋａ＠ｅｘａｍｐｌｅ．ｃｏｍ` は半角形と同じ規則で一致させる必要が
あるが、置換は**元の文字列**に対して行わなければ、利用者は崩れた文章を
受け取ることになる。`mamori` は文字単位のオフセット表を持って正規化するので、
正規化座標で見つけた範囲を元テキストへ正確に戻せる。

**検出器同士は食い違い、重なった置換は文章を壊す。**
`田中太郎(tanaka@example.com)` では3つの規則が重なる範囲を返す。
1文字につき1つの検出だけが勝つ必要があり、その規則は辞書順まかせにせず
明文化しなければならない。長い範囲が優先、次に重大度、確信度、開始位置の順。
広い範囲を置換すればその内側もまとめて消えるので、長さを最優先にしている。

## どれくらい効くのか

測れる。

```bash
mamori eval
```

```text
ja-core  (ja, 51 samples)
  leak rate             0.00%   (0/576 sensitive chars left uncovered)
  over-redaction        2.50%   (23/919 ordinary chars replaced)
  entity P / R / F1   0.868 / 0.983 / 0.922   (match: overlap)
  clean samples       49/49
```

**leak rate** は、正解ラベルの機微文字のうちどの検出にも覆われなかった割合。
すなわち**外部へ出てしまったはずの分量**である。
**over-redaction** はその代償として壊した通常文の割合。

**この2つは片方だけでは意味を持たない。** 全文を伏せれば leak rate は完璧に
なり、回答は全滅する。そして使われなくなったプライバシー層の実効 leak rate は
1.0 である。

エンティティ単位の precision / recall も型ごとに出しているが、主指標ではない。
`田中太郎` のうち `田中` だけを検出した場合、overlap 一致では成功、exact 一致
では失敗と出る。どちらも**「氏名が2文字、第三者に渡った」**という肝心のことを
言っていない。

品質下限値を CI に置いてあるので、ある言語を良くして別の言語を静かに壊す変更は
ビルドを赤くする。この評価セットを書いた1時間で**実バグが5件**見つかった。
内訳は [ADR 0009](docs/adr/0009-measure-leaked-characters.md) にある。

その後の各変更を入れる根拠になったのも、意見ではなくこの数値である。

| leak rate | v0.2 | + co-occurrence | + recall_first |
|---|---|---|---|
| `en-core` | 7.37% | 2.01% | **0.67%** |
| `ja-core` | 1.43% | 0.71% | **0.00%** |
| `zh-core` | 1.49% | 0.00% | **0.00%** |

co-occurrence は precision も over-redaction も悪化させずに効いた。
recall_first は over-redaction を約5倍にする代わりに残りを詰めた。
**2つの表は必ずセットで読むこと。**

なお**この数値は退行を止めるための下限であって、実データに対する主張ではない**。
評価セットは小さく、すべて合成である。49件の作り物の文で leak rate がほぼ 0 でも、
実際の受信箱について何も保証しない。

### モデル層は実際どれだけ効くのか

主張ではなく実測値。`llama3.1:8b` をローカルで動かし、balanced スタンスで
同梱データセットに対して測定した。

| | 漏洩率: 規則のみ → +モデル | 過剰検出 | precision |
|---|---|---|---|
| `en-core` | 2.01% → **0.67%** | 0.00% → 3.77% | 1.000 → 0.855 |
| `ja-core` | 0.71% → 0.71% | 0.00% → 5.41% | 1.000 → 0.868 |
| `zh-core` | 0.00% → 0.00% | 2.55% → 10.18% | 0.964 → 0.871 |

**このサイズでは「英語の再現率を上げる道具」である。**
手がかりの無い英文中の人名（`en-006`、このモデル層が想定していた当のケース）を
埋める一方、日本語・中国語には測定可能な改善がなく、3言語すべてで過剰検出が増える。
以前の README は「中国語の人名にも届く」と書いていたが、それは支持されなかった。
中国語の規則はそのデータセットで既に recall 1.000 だった。

**既定の recall_first では逆効果である。** wide 規則が既に届いているので漏洩率は動かず、
過剰検出だけが 1.44% → 9.58% に増える。自分のデータで測るまでは切っておくのがよい。

自分で測る。読む価値があるのは差分だけである。

```bash
mamori eval --compare --stance balanced -c mamori.json --cache answers.json
```

`--compare` は変化したサンプルを名前で挙げる。集計値は「何かが動いた」としか言わない。
**自分の文書で測る**手順（ここにある数字よりはるかに強い証拠になる）は
[docs/measuring-your-own-data.md](docs/measuring-your-own-data.md) にある。
そのファイルは自分の実データそのものになるので、注意点も併記した。
`--cache` はモデルと**プロンプト**でキーを作るので、再実行は無料で、
ガイダンスを1行書き換えるとそれに依存していた答えだけが無効になる。

この測定から2つの修正がコードに戻った。モデルに文字オフセットを要求していたが
**52件中0件しか正しくなかった**（値そのものは52件中51件が本当に文書内にあった）。
そこで値だけを報告させ、位置は mamori 側で特定するようにした
（[ADR 0022](docs/adr/0022-a-model-reports-values-not-offsets.md)）。
また英語の誤検出は全て `OTHER_SENSITIVE` のゴミ箱的使用だった。
この型が何のためのものかを述べたガイダンス1つで過剰検出は 8.80% → 4.43% に半減した。

## できないこと

ここは読んでほしい。実力以上に信頼されたセキュリティツールは、無いよりも
危険になる。ツールが許してしまう行動のほうが、置き換えた行動よりリスクが
高くなるからである。

- **検出は完全ではなく、今後も完全にはならない。** 既定の規則は正規表現で
  ある。珍しい姓で敬称の無い氏名、前置きの無い英語氏名、都道府県や街路種別の
  無い住所、普通名詞に見える社内コードネーム、文脈でのみ機微になる情報は
  取りこぼす。言語ごとの具体的な盲点は [SECURITY.md](SECURITY.md) にある。
- **`mamori` は漏洩の確率を下げるが、ゼロにはしない。** 「顧客データをチャットに
  貼らない」という運用ルールがあるなら、`mamori` はそれを変更する理由には
  ならない。あくまで、それでも貼ってしまったときの安全網である。
- **コンプライアンス対応の統制ではない。** GDPR / HIPAA / 個人情報保護法などに
  対する評価は一切行っていない。仮名化された個人データは、多くの制度で
  依然として個人データである。
- **既に侵害された端末は守れない。** 対応表には、守ろうとした値だけが
  集まっている。既定でメモリ上にしか置かないのは、まさにそのためである。
- **保護し忘れた送信は止められない。** `mamori` は呼ばれた場所でしか働かない。
  経由しない通信は捕捉できない。

各検出器が取りこぼす具体的な範囲を含む詳細は
[docs/threat-model.md](docs/threat-model.md)（英語）にある。

## 設計

4つの原則が他のすべてを決めている。

**外部モデルは信頼境界の外にある。** 検出・対応付け・ポリシー・復元は
ローカルかつ決定論的に行う。「何を送ってよいか」の判断が、データを
守ろうとしている当の相手に依存することはない。

**モデルをセキュリティ機構にしない。** 将来のバージョンでは候補の*発見*に
ローカルモデルを使う。それはモデルが得意な仕事である。候補をどう扱うか、
プレースホルダをどう払い出すか、値をどう戻すかは、読んでテストできる
コードの側に残す。

**Fail-Closed。** 検出器が例外を投げれば処理は止まる。ポリシーが拒否すれば
処理は止まる。部分的な結果は返さない。呼び出し側から見て、部分的な結果は
安全な結果と見分けがつかないからである。

**資格情報は仮名化ではなく遮断する。** APIキーを第三者に送ってよい理由は
存在しない。プレースホルダの形であっても、「そこに鍵がある」という事実を
相手に伝えてしまう。

```text
interfaces ──> application ──> domain
                    │
infrastructure ──> ports
```

`domain/` は Python標準ライブラリ以外を一切importしない。セキュリティに
関わる判断はすべてそこにあり、モデルもネットワークもDBも無しでテストできる。

## ロードマップ

`v0.1` は中核部分。検出し、判断し、仮名化し、復元する。メモリ上で、
Pythonからもシェルからも。

`v0.2` で測定基盤とストリーミング復元を追加。
`v0.3` で検出をパイプライン化し、切り替え可能な設定を1つに集約。
`v0.4` で既定を「漏らさない側」に倒し、プロンプト層を構築した。
`v0.5` でモデルの所在もクライアントライブラリも設定項目にし、
層構造を「図」ではなく「テスト」にした。
`v0.6` でプロキシを出し、プライバシー上の主張を「問い合わせられるもの」かつ
「機械で検査されるもの」にした。
`v0.7` でモデル層を初めて測定し、モデルが正しく答えた内容を
ほぼ全て捨てていたことを見つけて直した。
`v0.8` で最終判断を運用者の手に渡した。
`v0.9` で評価データを文書規模にし、44文字の標本では見えなかった検出バグを4件見つけた。
`v0.10` で実際に動くデモを追加し、測定基盤自体のバグを見つけた。
`v0.11` で代替値を追加した（既定では無効）。
`v0.12` で「なぜそうなったのか」を言えるようにした。
`v0.13` で日本語と中国語に手を入れ、**失敗した2つの修正から、成功した2つより多くを学んだ。**
`v0.14` で文書1000本と応答1000本を生成し、1時間で5件のバグを見つけた。
`v0.15` はそのコーパスを中国語に使い、**初版から見えていなかった穴**——後ろに普通の語が続く氏名——を塞いだ。
`v0.16` はプロキシに会話を持たせ、4リリース放置されていた論拠を初めて検証した（正しかった）。
`v0.17` は「誰も打っていないプロンプト」にコーパスを向け、4件のバグを見つけた。うち3件は組み立てプロンプト固有ではなく、何リリースも前から存在していたものである。
`v0.18` では、**ツール呼び出しの引数が一度も保護されていなかった**ことが分かった。
`v0.19` は運用のためのリリースで、そのリンタは初回実行でこのリポジトリ自身のバグを見つけた。
`v0.20` は復元側を `v0.2` 以来の検出側と同じ規模で測り、**ストリーミングと一括で結果が4リリース分食い違っていた**ことを見つけた。
`v0.21` は同じことを代替値に対して行い、ドキュメント中で最も恐ろしい段落を2つの数字に変えた。
`v0.22` で初めて**時間**を測り、0.5MBの文書に13秒かかる二次オーダーの処理を見つけた。
`v0.23` は `v0.7` が残した問い——8Bより大きいモデルで表は変わるか——に答えた。答えは「変わる」。そして測れなかった理由は、**このライブラリがタイムアウト設定を無視していたこと**だった。
`v0.24` は同じ測定を日本語と中国語で行い、ロードマップ最後の項目を「測って、断る」ことで閉じた。

| | |
|---|---|
| **v0.17** | 組み立てられたプロンプト。いまやプロンプトは人が打つものではなく、検索層やエージェント基盤が**描画**するものになりつつある。ヘッダにはファイルパス、構造にはハッシュが入る。これも他と同じく生成コーパスで測る。しかも構造部分は**負例**として測る——IDが置換されたら、それは数字の付いたバグである。 |
| **v0.18** | 運用向け。見落とすより止まることを選ぶfail-closedスタンス、コミットしてはいけない値を探すCIリンタ、HTML中の `<PERSON_001>`、そしてJSONの2つのキーに分かれた氏名。 |
| **v1.0** | 機能ではない。APIの安定、約束スイートを仕様とすること、そして「実測」と呼ぶに値するデータに裏付けられた数字。 |

この表の理由——**計画して実現しなかったもの**、**採用したが不要と判明したもの**、
そして**あえて計画に入れていないもの**は
[docs/proposals/0003](docs/proposals/0003-what-mamori-is-for.md) にある。

2つの項目は、望まれてはいるが**あえてバージョン番号を付けていない**。日本語の
形態素解析アダプタ（任意インストール）と、メモリだけでは運用できない環境向けの
暗号化ストアである。3度目の番号付けは、「その週にコーパスが見つけたもの」に
毎回負け続けている事実を認めない言い訳になる。最も古い未解決の問いは、いまだに
8Bより大きいモデルでモデル層の表が変わるかどうか。測る仕組みはある。この環境の
ハードウェアがタイムアウトする。

言語の優先度は**日本語と英語が主、中国語が次点**。中国語の規則は実装済みで
測定もしているが、正規表現では原理的に解けない部分がある。その分析と
段階的な解き方は [ADR 0008](docs/adr/0008-language-packs.md) に書いてある。
