# mamori 守り

**実データのまま生成AIを使う。実データは送らずに。**

English: [README.md](README.md) ／ 中文: [README.zh.md](README.zh.md)

顧客からのメールが目の前にあり、返信の下書きを数秒で書けるモデルもある。
だから氏名を伏せて打ち直し、伏せ字の付け方が途中でぶれ、署名欄の電話番号を
見落とし、結局は自分で書いたほうがましな下書きができあがる。

`mamori` はその作業を、ローカルで、一貫したやり方で肩代わりする。

```text
あなたが書く                    モデルが見る                   あなたが受け取る
─────────────────────────────  ─────────────────────────────  ─────────────────────────────
田中太郎さんへ                  <PERSON_001>さんへ              田中太郎さんへ
tanaka@example.com から        <EMAIL_001> から                tanaka@example.com から
メールが届きました。            メールが届きました。             メールが届きました。
```

`<PERSON_001>` から `田中太郎` に戻す対応表が手元の端末を出ることはない。

---

## インストール

```bash
pip install mamori
```

モデル不要、GPU不要、通信なし。既定の検出器はマイクロ秒で動くパターン規則。

## 使い方

```python
import mamori

with mamori.PrivacySession() as session:
    protected = session.protect("田中太郎さんに tanaka@example.com で連絡して")
    # -> '<PERSON_001>さんに <EMAIL_001> で連絡して'

    answer = call_your_favourite_llm(protected.protected_text)

    print(session.restore(answer).text)
```

1つのセッションが1つの会話にあたる。同じ値はセッションが続くかぎり同じ
プレースホルダを保つので、モデルは2箇所の言及が同一人物だと判断でき、
5ターン目の応答も1ターン目の値で復元できる。

### ストリーミング

応答はトークン単位で届くので、`<PERSON_001>` は `<PER` / `SON_0` / `01>` に
分かれてやってくる。届いたそばから復元できる。

```python
stream = session.stream_restore()
for chunk in llm_response_stream:
    print(stream.feed(chunk), end="", flush=True)
print(stream.finish())
```

どのような分割で流れてきても、**応答全体を `restore()` にかけた結果と
1文字も違わない**。Hypothesis であらゆる分割位置を検証している。
「たいてい一致する」ストリーミング実装は、モデルが選んだトークン境界次第で
壊れる。再現しないうえ、実データが崩れて初めて気付く。

### コマンドラインから

```bash
mamori inspect -f draft.txt
```

```text
4 detected:
      0:4     PERSON           <PERSON_001>       田***                (ja, 0.90)
     12:30    EMAIL            <EMAIL_001>        t*****************   (universal, 1.00)
     45:58    PHONE            <PHONE_001>        0************        (ja, 0.90)
     70:94    INTERNAL_URL     <INTERNAL_URL_001> h***********************  (universal, 0.90)
```

最後の列は命中した規則セットで、どの言語のパックが見つけたかがわかる。
`mamori demo` は往復全体を実行する。プレースホルダが改変されて返ってきた
応答も含むので、復旧の挙動をそのまま確認できる。

## 対応言語

日本語・英語・中国語。1つの文書に混在していても扱える。

```text
田中太郎さんへ                        ->  <PERSON_001>さんへ
CC: Mr. John Smith (Acme Inc.)       ->  CC: Mr. <PERSON_003> (<COMPANY_NAME_002>)
张伟先生，请拨打 13812345678          ->  <PERSON_004>先生，请拨打 <PHONE_003>
```

規則は言語パックに分かれており、テキストが根拠を示したパックだけが動く。
既定では全パックが有効になる。**文書に想定外の言語が混じっている状況こそ、
誰も手作業で伏せていない状況**だからである。範囲がわかっている場合は
`locales=` で絞る。

```python
mamori.PrivacySession(locales=["ja", "en"])
```

```bash
mamori locales
```

```text
  en  English     16 rules  runs on: latin
  ja  Japanese    11 rules  runs on: han, kana
  zh  Chinese     11 rules  runs on: han  (not when: kana)
```

肝は最後の行にある。中国語と日本語は漢字を共有するため、両者の姓リストは
互いのテキスト上で発火し続け、普通の語を人名に変えてしまう。
判定材料になるのは仮名である。仮名は日本語には現れ、中国語には決して現れない。
したがってテキストに仮名があれば中国語規則は停止する。漢字のみの場合は
判定できないので両方を走らせ、過剰検出する側に倒す。
プレースホルダが1つ増える損失は回答品質だが、名前を1つ見逃す損失は
このライブラリが存在する理由そのものだからである。

メールアドレス・資格情報・カード番号・内部アドレスは言語非依存で常に動く。
言語の追加はモジュール1つと登録1行で済む（`register_locale` を参照）。

## 難しいのは3か所

`mamori` の実装量の大半は、素朴に作ると必ず間違える部分に費やされている。

**モデルはプレースホルダをそのまま返さない。** `<PERSON_001>` は `PERSON_001`、
`<PERSON_1>`、`<person_001>`、`＜PERSON_001＞` になって戻ってくる。
復元処理は**表記には寛容、同一性には厳格**に作ってある。正規化した
`(型, 番号)` の組がそのセッションで実際に払い出されたものと一致したときだけ
置換する。それ以外は報告するだけで解決しない。応答は信用できない入力であり、
応答側が選んだ文字列で対応表を引かせることは、対応表を1回1件ずつ読み出させる
ことに等しい。

**日本語には語境界が無く、正規化するとオフセットがずれる。**
`ｔａｎａｋａ＠ｅｘａｍｐｌｅ．ｃｏｍ` は半角形と同じ規則で一致させる必要が
あるが、置換は**元の文字列**に対して行わなければ、利用者は崩れた文章を
受け取ることになる。`mamori` は文字単位のオフセット表を持って正規化するので、
正規化座標で見つけた範囲を元テキストへ正確に戻せる。

**検出器同士は食い違い、重なった置換は文章を壊す。**
`田中太郎(tanaka@example.com)` では3つの規則が重なる範囲を返す。
1文字につき1つの検出だけが勝つ必要があり、その規則は辞書順まかせにせず
明文化しなければならない。長い範囲が優先、次に重大度、確信度、開始位置の順。
広い範囲を置換すればその内側もまとめて消えるので、長さを最優先にしている。

## どれくらい効くのか

測れる。

```bash
mamori eval
```

```text
ja-core  (ja, 45 samples)
  leak rate             0.75%   (4/531 sensitive chars left uncovered)
  over-redaction        0.00%   (0/803 ordinary chars replaced)
  entity P / R / F1   1.000 / 0.981 / 0.990   (match: overlap)
  clean samples       44/45
```

**leak rate** は、正解ラベルの機微文字のうちどの検出にも覆われなかった割合。
すなわち**外部へ出てしまったはずの分量**である。
**over-redaction** はその代償として壊した通常文の割合。

**この2つは片方だけでは意味を持たない。** 全文を伏せれば leak rate は完璧に
なり、回答は全滅する。そして使われなくなったプライバシー層の実効 leak rate は
1.0 である。

エンティティ単位の precision / recall も型ごとに出しているが、主指標ではない。
`田中太郎` のうち `田中` だけを検出した場合、overlap 一致では成功、exact 一致
では失敗と出る。どちらも**「氏名が2文字、第三者に渡った」**という肝心のことを
言っていない。

品質下限値を CI に置いてあるので、ある言語を良くして別の言語を静かに壊す変更は
ビルドを赤くする。この評価セットを書いた1時間で**実バグが5件**見つかった。
内訳は [ADR 0009](docs/adr/0009-measure-leaked-characters.md) にある。

なお**この数値は退行を止めるための下限であって、実データに対する主張ではない**。
評価セットは小さく、すべて合成である。45件の作り物の文で leak rate がほぼ 0 でも、
実際の受信箱について何も保証しない。

## できないこと

ここは読んでほしい。実力以上に信頼されたセキュリティツールは、無いよりも
危険になる。ツールが許してしまう行動のほうが、置き換えた行動よりリスクが
高くなるからである。

- **検出は完全ではなく、今後も完全にはならない。** 既定の規則は正規表現で
  ある。珍しい姓で敬称の無い氏名、前置きの無い英語氏名、都道府県や街路種別の
  無い住所、普通名詞に見える社内コードネーム、文脈でのみ機微になる情報は
  取りこぼす。言語ごとの具体的な盲点は [SECURITY.md](SECURITY.md) にある。
- **`mamori` は漏洩の確率を下げるが、ゼロにはしない。** 「顧客データをチャットに
  貼らない」という運用ルールがあるなら、`mamori` はそれを変更する理由には
  ならない。あくまで、それでも貼ってしまったときの安全網である。
- **コンプライアンス対応の統制ではない。** GDPR / HIPAA / 個人情報保護法などに
  対する評価は一切行っていない。仮名化された個人データは、多くの制度で
  依然として個人データである。
- **既に侵害された端末は守れない。** 対応表には、守ろうとした値だけが
  集まっている。既定でメモリ上にしか置かないのは、まさにそのためである。
- **保護し忘れた送信は止められない。** `mamori` は呼ばれた場所でしか働かない。
  経由しない通信は捕捉できない。

各検出器が取りこぼす具体的な範囲を含む詳細は
[docs/threat-model.md](docs/threat-model.md)（英語）にある。

## 設計

4つの原則が他のすべてを決めている。

**外部モデルは信頼境界の外にある。** 検出・対応付け・ポリシー・復元は
ローカルかつ決定論的に行う。「何を送ってよいか」の判断が、データを
守ろうとしている当の相手に依存することはない。

**モデルをセキュリティ機構にしない。** 将来のバージョンでは候補の*発見*に
ローカルモデルを使う。それはモデルが得意な仕事である。候補をどう扱うか、
プレースホルダをどう払い出すか、値をどう戻すかは、読んでテストできる
コードの側に残す。

**Fail-Closed。** 検出器が例外を投げれば処理は止まる。ポリシーが拒否すれば
処理は止まる。部分的な結果は返さない。呼び出し側から見て、部分的な結果は
安全な結果と見分けがつかないからである。

**資格情報は仮名化ではなく遮断する。** APIキーを第三者に送ってよい理由は
存在しない。プレースホルダの形であっても、「そこに鍵がある」という事実を
相手に伝えてしまう。

```text
interfaces ──> application ──> domain
                    │
infrastructure ──> ports
```

`domain/` は Python標準ライブラリ以外を一切importしない。セキュリティに
関わる判断はすべてそこにあり、モデルもネットワークもDBも無しでテストできる。

## ロードマップ

`v0.1` は中核部分。検出し、判断し、仮名化し、復元する。メモリ上で、
Pythonからもシェルからも。

`v0.2` で測定基盤、ストリーミング復元、英語・中国語パックを追加した。

| | |
|---|---|
| **v0.3** | OpenAI互換のローカルプロキシ。既存アプリは `base_url` を変えるだけで移行できる。あわせて**同一文書内の共起**：高信頼で一度確定した氏名は、以降の出現もすべて高信頼で拾う。 |
| **v0.4** | Presidioアダプタ、opt-inの暗号化永続ストア、confidence 下限値の設定（回答品質と網羅性を利用者が選べるようにする）。 |
| **v0.5** | ローカルモデル検出を opt-in の深掃引ティアとして追加。パターンでは届かない領域、とりわけ前置きの無い英語氏名と中国語の人名向け。 |
| **v0.6** | 代替値方式（`田中太郎` → `山田一郎`）をポリシー選択肢として追加。不透明なトークンでは回答品質の低下が大きすぎる用途向け。 |

プロキシを次に置いたのは意図的である。動いているアプリをライブラリの
ために書き直す人はいない。新規コードしか守れないプライバシー層が守れる
範囲はごくわずかである。

言語の優先度は**日本語と英語が主、中国語が次点**。中国語の規則は実装済みで
測定もしているが、正規表現では原理的に解けない部分がある。その分析と
段階的な解き方は [ADR 0008](docs/adr/0008-language-packs.md) に書いてある。
