# mamori 守り

**実データのまま生成AIを使う。実データは送らずに。**

English: [README.md](README.md) ／ 中文: [README.zh.md](README.zh.md)

顧客からのメールが目の前にあり、返信の下書きを数秒で書けるモデルもある。
だから氏名を伏せて打ち直し、伏せ字の付け方が途中でぶれ、署名欄の電話番号を
見落とし、結局は自分で書いたほうがましな下書きができあがる。

`mamori` はその作業を、ローカルで、一貫したやり方で肩代わりする。

```text
あなたが書く                    モデルが見る                   あなたが受け取る
─────────────────────────────  ─────────────────────────────  ─────────────────────────────
田中太郎さんへ                  <PERSON_001>さんへ              田中太郎さんへ
tanaka@example.com から        <EMAIL_001> から                tanaka@example.com から
メールが届きました。            メールが届きました。             メールが届きました。
```

`<PERSON_001>` から `田中太郎` に戻す対応表が手元の端末を出ることはない。

---

## インストール

```bash
pip install mamori
```

モデル不要、GPU不要、通信なし。既定の検出器はマイクロ秒で動くパターン規則。

## 使い方

```python
import mamori

with mamori.PrivacySession() as session:
    protected = session.protect("田中太郎さんに tanaka@example.com で連絡して")
    # -> '<PERSON_001>さんに <EMAIL_001> で連絡して'

    answer = call_your_favourite_llm(protected.protected_text)

    print(session.restore(answer).text)
```

1つのセッションが1つの会話にあたる。同じ値はセッションが続くかぎり同じ
プレースホルダを保つので、モデルは2箇所の言及が同一人物だと判断でき、
5ターン目の応答も1ターン目の値で復元できる。

### ストリーミング

応答はトークン単位で届くので、`<PERSON_001>` は `<PER` / `SON_0` / `01>` に
分かれてやってくる。届いたそばから復元できる。

```python
stream = session.stream_restore()
for chunk in llm_response_stream:
    print(stream.feed(chunk), end="", flush=True)
print(stream.finish())
```

どのような分割で流れてきても、**応答全体を `restore()` にかけた結果と
1文字も違わない**。Hypothesis であらゆる分割位置を検証している。
「たいてい一致する」ストリーミング実装は、モデルが選んだトークン境界次第で
壊れる。再現しないうえ、実データが崩れて初めて気付く。

### コマンドラインから

```bash
mamori inspect -f draft.txt
```

```text
4 detected:
      0:4     PERSON           <PERSON_001>       田***                (ja, 0.90)
     12:30    EMAIL            <EMAIL_001>        t*****************   (universal, 1.00)
     45:58    PHONE            <PHONE_001>        0************        (ja, 0.90)
     70:94    INTERNAL_URL     <INTERNAL_URL_001> h***********************  (universal, 0.90)
```

最後の列は命中した規則セットで、どの言語のパックが見つけたかがわかる。
`mamori demo` は往復全体を実行する。プレースホルダが改変されて返ってきた
応答も含むので、復旧の挙動をそのまま確認できる。

## 対応言語

日本語・英語・中国語。1つの文書に混在していても扱える。

```text
田中太郎さんへ                        ->  <PERSON_001>さんへ
CC: Mr. John Smith (Acme Inc.)       ->  CC: Mr. <PERSON_003> (<COMPANY_NAME_002>)
张伟先生，请拨打 13812345678          ->  <PERSON_004>先生，请拨打 <PHONE_003>
```

規則は言語パックに分かれており、テキストが根拠を示したパックだけが動く。
既定では全パックが有効になる。**文書に想定外の言語が混じっている状況こそ、
誰も手作業で伏せていない状況**だからである。範囲がわかっている場合は
`locales=` で絞る。

```python
mamori.PrivacySession(locales=["ja", "en"])
```

```bash
mamori locales
```

```text
  en  English     16 rules  runs on: latin
  ja  Japanese    11 rules  runs on: han, kana
  zh  Chinese     11 rules  runs on: han  (not when: kana)
```

肝は最後の行にある。中国語と日本語は漢字を共有するため、両者の姓リストは
互いのテキスト上で発火し続け、普通の語を人名に変えてしまう。
判定材料になるのは仮名である。仮名は日本語には現れ、中国語には決して現れない。
したがってテキストに仮名があれば中国語規則は停止する。漢字のみの場合は
判定できないので両方を走らせ、過剰検出する側に倒す。
プレースホルダが1つ増える損失は回答品質だが、名前を1つ見逃す損失は
このライブラリが存在する理由そのものだからである。

メールアドレス・資格情報・カード番号・内部アドレスは言語非依存で常に動く。
言語の追加はモジュール1つと登録1行で済む（`register_locale` を参照）。

## 切り替えられる

検出は固定の手順ではなく、**パスの並び**である。各パスはテキストと
「それまでのパスが見つけたもの」の両方を見る。

```text
rules            汎用パターン + 該当する言語パック
  ↓
co-occurrence    しきい値以上の確信度で確定した値を、
                 同じテキスト内の他の出現箇所でも拾う
```

2つ目のパスが必要な理由はこれである。**ある文で敬称によって氏名が確定したら、
同じ文書の他の言及も同じ人物である。**しかし個々の言及だけを見る規則には
それが分からない。

```text
尊敬的张伟先生：              ← 敬称で確定する
本次评审由张伟主持。           ← ここには何の手がかりも無い
请张伟在周五前回复。           ← ここにも無い
```

3箇所とも保護される。中国語ではこれは最適化ではなく、
**他に手がかりが存在しない**ため必須である。

切り替え可能な設定はすべて1つのオブジェクトに集約した。

```python
mamori.PrivacySession(
    config=mamori.MamoriConfig(
        locales=["ja", "en"],
        min_confidence=0.7,  # 確信度の低い検出を無視：誤検出は減り、網羅性も下がる
        co_occurrence=True,
    )
)
```

`MamoriConfig` はファイル形式について何の意見も持たない。
`from_mapping()` は**解析済みのマッピング**を受け取るので、
JSON / TOML / YAML / dict リテラルのどれを使うかは呼び出し側が決める。
ライブラリ本体のランタイム依存は引き続きゼロである。

```bash
mamori config                       # 実際に使われる設定と、どの層から来たか
mamori protect --min-confidence 0.7 -f draft.txt
```

設定は後勝ちで重なる：既定値 → `--config` → `MAMORI_*` 環境変数 → コマンドライン引数。
**未知のキーは無視せず拒否する。** プライバシー設定のタイプミスが黙って
無視されるのは最悪の結果である（締めたつもりで締まっていない）。

### 匿名化漏れを優先する

各規則は**ティア**を宣言する。**core** は「それ以外である可能性が低いもの」に
固定された規則——チェックディジット、ベンダー接頭辞、敬称、ラベル。
**wide** は形だけで判断する規則——数字10桁、大文字始まりの2語、
長いランダム風トークン。どちらを走らせるかは stance が決め、
**既定は recall_first**（wide も走らせる）である。

| | leak rate | | over-redaction | |
|---|---|---|---|---|
| | balanced | **recall_first** | balanced | **recall_first** |
| `ja-core` | 0.71% | **0.00%** | 0.00% | **3.11%** |
| `en-core` | 2.01% | **0.67%** | 0.66% | **1.44%** |
| `zh-core` | 0.00% | **0.00%** | 2.55% | **4.00%** |

これがトレードオフである。埋もれさせずに書いておく。
**見逃しは静かで取り返しがつかない。誤検出は「置換すべきでない語が置換された」
という目に見える形で現れる。** 保護後テキストを読んだ人は後者に気付くが、
置換されなかった氏名には誰も気付かない。

```bash
mamori protect --stance balanced -f draft.txt   # 誤検出を減らしたいとき
mamori eval --stance balanced                   # どちらも測れる
```

**stance はセキュリティ上の判断を一切変えない。** 何を送ってよいかはポリシーが
決め、1文字につき1検出という解決も変わらず、資格情報は依然として遮断される。
stance が変えるのは「候補を何件出すか」だけである。だからこそ
「recall_first は balanced より漏らすことがない」を**テストとして固定**できる。

wide 規則は LOW confidence なので、stance を変えずに `min_confidence` で
落とすこともできる。同じトレードオフに対する粒度違いの2つのつまみである。

## プロンプト

関わるモデルは2つあり、向きが逆である。どちらのプロンプトも読めて変更できる。

**サービスLLM**にはプレースホルダをそのまま返すよう伝える。
ローカルモデルは不要で、即座に元が取れる。

```python
system = session.external_system_prompt() + "

" + your_own_system_prompt
```

無傷で返ってきたプレースホルダは、復元処理が改変から復旧しなくて済んだ分である。

**ローカルLLM**にはパターンでは届かない対象を探させる。
前置きの無い英語氏名、中国語の人名、普通名詞に見えるコードネーム。
そのプロンプトには**正規表現の作業で得た知見をすべて載せてある**。

```bash
mamori prompt detection
```

```text
## What looks sensitive and is not

- Many ordinary words begin with a character that is also a surname. 森林 is a
  forest, not 森 and 林. 原因, 金額, 石油, 田舎 and 林檎 are words.
- Two capitalised words are usually not a name. Headings, products, departments,
  weekdays and sentence openers all look identical.
```

これらは**正規表現についての知識ではなく、言語についての知識**だからである。

### 社内ルールを足す・既存ルールを削る

guidance は1件ずつ ID を持つ。ライブラリが知りようのないことを足し、
合わないものを外せる。**フォーク不要**。

```json
{"prompts": {"detection": {
  "disable": ["en.person.unanchored"],
  "add": [{"id": "acme.case", "text": "案件番号は ACME-12345 の形式である。"}]
}}}
```

```bash
mamori prompt detection --guidance   # ID一覧。ここから disable できる
```

**存在しない ID の disable は拒否する。** しかも設定を読み込んだ時点で拒否する
（何ヶ月も後ではなく）。外したつもりで外れていない状態を作らないためである。

### モデルを繋ぐ ― 同じPCでも、社内サーバーでも

現実的な構成はノートPCではない。チームで共有する1台のGPUマシンである。

```json
{"llm": {"model": "qwen2.5:72b", "base_url": "http://llm01.corp:8000/v1/"}}
```

```bash
mamori llm --check     # どこにあるか、許可されるか、応答するか
```

```text
  model           qwen2.5:72b
  endpoint        http://llm01.corp:8000/v1/
  host            private (another machine)
  trust boundary  private_network
  reachable       yes
```

`base_url` を書かなければ同じPC上のモデルを使う。他に変えるものは何もない。

拒否されるのは**公開エンドポイント**である。検出器は保護*前*のテキストを
受け取るので、社内ネットワークの外にあるエンドポイントは検出器ではなく
漏洩経路そのものである。しかもそれを最初の1件を処理する時ではなく、
起動時に告げる。

```text
REFUSED. This model will not be used:
  'api.openai.com' looks external, which is outside the private_network trust
  boundary.
```

境界は3つ。`same_host` / `private_network`（既定）/ `anywhere`。
`trusted_hosts` に明記されたホストはどの境界でも許可される ―
運用者がホストを名指しするのは「判断した」ということだからである。
→ [ADR 0015](docs/adr/0015-a-trust-boundary-not-a-localhost-check.md)

### モデルもライブラリも差し替えられる

モデルの切り替えは設定項目1つ。*繋ぎ方*の切り替えも1行で、
このライブラリに依存関係は増えない。

```python
from mamori.infrastructure.llm import CallableProvider, register_llm_provider

# 既に同一プロセス内に読み込まれているモデル。ライブラリは何でもよく、HTTPも不要。
provider = CallableProvider(my_pipeline, name="local-transformers")

# 設定ファイルから名前で選べるようにする。
register_llm_provider("vllm", lambda endpoint: MyVLLMProvider(endpoint))
```

```python
from mamori import MamoriConfig
session = MamoriConfig.from_mapping(settings).session()
```

同梱の Provider は `urllib` だけで OpenAI 互換 HTTP を話す。
実行時依存ゼロはゼロのままである。
→ [ADR 0016](docs/adr/0016-the-model-and-the-client-are-both-replaceable.md)

モデルが何をしようと、次の3つが成り立つ。

- **増やすことしかできない。** 「何も報告するな」と言い含められても、
  結果は規則だけの状態に戻るだけ。それは前バージョンまでの出荷状態である。
- **出力はテキストと照合される。** オフセットが範囲内にあり、報告された値が
  その区間の文字と完全一致しなければ破棄する。幻覚したスパンが文書から
  切り取られることはない。
- **モデルの失敗はリクエストの失敗ではない。** モデルが無い・遅い・壊れている
  のは「検出器が弱い」状態であって、処理停止ではない。
  `require_model` で逆にできる。

APIキーは設定ファイルには書かない。環境変数名を指定する
（`{"api_key_env": "LLM_API_KEY"}`）。リテラルの `api_key` は拒否する。

## 難しいのは3か所

`mamori` の実装量の大半は、素朴に作ると必ず間違える部分に費やされている。

**モデルはプレースホルダをそのまま返さない。** `<PERSON_001>` は `PERSON_001`、
`<PERSON_1>`、`<person_001>`、`＜PERSON_001＞` になって戻ってくる。
復元処理は**表記には寛容、同一性には厳格**に作ってある。正規化した
`(型, 番号)` の組がそのセッションで実際に払い出されたものと一致したときだけ
置換する。それ以外は報告するだけで解決しない。応答は信用できない入力であり、
応答側が選んだ文字列で対応表を引かせることは、対応表を1回1件ずつ読み出させる
ことに等しい。

**日本語には語境界が無く、正規化するとオフセットがずれる。**
`ｔａｎａｋａ＠ｅｘａｍｐｌｅ．ｃｏｍ` は半角形と同じ規則で一致させる必要が
あるが、置換は**元の文字列**に対して行わなければ、利用者は崩れた文章を
受け取ることになる。`mamori` は文字単位のオフセット表を持って正規化するので、
正規化座標で見つけた範囲を元テキストへ正確に戻せる。

**検出器同士は食い違い、重なった置換は文章を壊す。**
`田中太郎(tanaka@example.com)` では3つの規則が重なる範囲を返す。
1文字につき1つの検出だけが勝つ必要があり、その規則は辞書順まかせにせず
明文化しなければならない。長い範囲が優先、次に重大度、確信度、開始位置の順。
広い範囲を置換すればその内側もまとめて消えるので、長さを最優先にしている。

## どれくらい効くのか

測れる。

```bash
mamori eval
```

```text
ja-core  (ja, 49 samples)
  leak rate             0.00%   (0/561 sensitive chars left uncovered)
  over-redaction        3.11%   (27/869 ordinary chars replaced)
  entity P / R / F1   0.868 / 0.983 / 0.922   (match: overlap)
  clean samples       49/49
```

**leak rate** は、正解ラベルの機微文字のうちどの検出にも覆われなかった割合。
すなわち**外部へ出てしまったはずの分量**である。
**over-redaction** はその代償として壊した通常文の割合。

**この2つは片方だけでは意味を持たない。** 全文を伏せれば leak rate は完璧に
なり、回答は全滅する。そして使われなくなったプライバシー層の実効 leak rate は
1.0 である。

エンティティ単位の precision / recall も型ごとに出しているが、主指標ではない。
`田中太郎` のうち `田中` だけを検出した場合、overlap 一致では成功、exact 一致
では失敗と出る。どちらも**「氏名が2文字、第三者に渡った」**という肝心のことを
言っていない。

品質下限値を CI に置いてあるので、ある言語を良くして別の言語を静かに壊す変更は
ビルドを赤くする。この評価セットを書いた1時間で**実バグが5件**見つかった。
内訳は [ADR 0009](docs/adr/0009-measure-leaked-characters.md) にある。

その後の各変更を入れる根拠になったのも、意見ではなくこの数値である。

| leak rate | v0.2 | + co-occurrence | + recall_first |
|---|---|---|---|
| `en-core` | 7.37% | 2.01% | **0.67%** |
| `ja-core` | 1.43% | 0.71% | **0.00%** |
| `zh-core` | 1.49% | 0.00% | **0.00%** |

co-occurrence は precision も over-redaction も悪化させずに効いた。
recall_first は over-redaction を約5倍にする代わりに残りを詰めた。
**2つの表は必ずセットで読むこと。**

なお**この数値は退行を止めるための下限であって、実データに対する主張ではない**。
評価セットは小さく、すべて合成である。49件の作り物の文で leak rate がほぼ 0 でも、
実際の受信箱について何も保証しない。

## できないこと

ここは読んでほしい。実力以上に信頼されたセキュリティツールは、無いよりも
危険になる。ツールが許してしまう行動のほうが、置き換えた行動よりリスクが
高くなるからである。

- **検出は完全ではなく、今後も完全にはならない。** 既定の規則は正規表現で
  ある。珍しい姓で敬称の無い氏名、前置きの無い英語氏名、都道府県や街路種別の
  無い住所、普通名詞に見える社内コードネーム、文脈でのみ機微になる情報は
  取りこぼす。言語ごとの具体的な盲点は [SECURITY.md](SECURITY.md) にある。
- **`mamori` は漏洩の確率を下げるが、ゼロにはしない。** 「顧客データをチャットに
  貼らない」という運用ルールがあるなら、`mamori` はそれを変更する理由には
  ならない。あくまで、それでも貼ってしまったときの安全網である。
- **コンプライアンス対応の統制ではない。** GDPR / HIPAA / 個人情報保護法などに
  対する評価は一切行っていない。仮名化された個人データは、多くの制度で
  依然として個人データである。
- **既に侵害された端末は守れない。** 対応表には、守ろうとした値だけが
  集まっている。既定でメモリ上にしか置かないのは、まさにそのためである。
- **保護し忘れた送信は止められない。** `mamori` は呼ばれた場所でしか働かない。
  経由しない通信は捕捉できない。

各検出器が取りこぼす具体的な範囲を含む詳細は
[docs/threat-model.md](docs/threat-model.md)（英語）にある。

## 設計

4つの原則が他のすべてを決めている。

**外部モデルは信頼境界の外にある。** 検出・対応付け・ポリシー・復元は
ローカルかつ決定論的に行う。「何を送ってよいか」の判断が、データを
守ろうとしている当の相手に依存することはない。

**モデルをセキュリティ機構にしない。** 将来のバージョンでは候補の*発見*に
ローカルモデルを使う。それはモデルが得意な仕事である。候補をどう扱うか、
プレースホルダをどう払い出すか、値をどう戻すかは、読んでテストできる
コードの側に残す。

**Fail-Closed。** 検出器が例外を投げれば処理は止まる。ポリシーが拒否すれば
処理は止まる。部分的な結果は返さない。呼び出し側から見て、部分的な結果は
安全な結果と見分けがつかないからである。

**資格情報は仮名化ではなく遮断する。** APIキーを第三者に送ってよい理由は
存在しない。プレースホルダの形であっても、「そこに鍵がある」という事実を
相手に伝えてしまう。

```text
interfaces ──> application ──> domain
                    │
infrastructure ──> ports
```

`domain/` は Python標準ライブラリ以外を一切importしない。セキュリティに
関わる判断はすべてそこにあり、モデルもネットワークもDBも無しでテストできる。

## ロードマップ

`v0.1` は中核部分。検出し、判断し、仮名化し、復元する。メモリ上で、
Pythonからもシェルからも。

`v0.2` で測定基盤とストリーミング復元を追加。
`v0.3` で検出をパイプライン化し、切り替え可能な設定を1つに集約。
`v0.4` で既定を「漏らさない側」に倒し、プロンプト層を構築した。
`v0.5` でモデルの所在もクライアントライブラリも設定項目にし、
層構造を「図」ではなく「テスト」にした。

| | |
|---|---|
| **v0.6** | OpenAI互換のローカルプロキシ。既存アプリは `base_url` を変えるだけで移行できる。 |
| **v0.7** | モデルパスを同じ評価セットで測定し、その数値に基づいてプロンプトを調整する（好みではなく）。測定に必要なものは既に揃っている。 |
| **v0.8** | Presidioアダプタ、opt-inの暗号化永続ストア。 |
| **v0.9** | 代替値方式（`田中太郎` → `山田一郎`）をポリシー選択肢として追加。 |

次はプロキシである。動いているアプリをライブラリのために書き直す人はいない。
新規コードしか守れないプライバシー層が守れる範囲はごくわずかである。

言語の優先度は**日本語と英語が主、中国語が次点**。中国語の規則は実装済みで
測定もしているが、正規表現では原理的に解けない部分がある。その分析と
段階的な解き方は [ADR 0008](docs/adr/0008-language-packs.md) に書いてある。
